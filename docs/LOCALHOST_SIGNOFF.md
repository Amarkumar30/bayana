## Defects found by this sign-off

- **Concurrent webhook retries could flag a good refund for review** (apps/api/src/payments/service.ts, `applyProviderRefund`). A refund created at Razorpay that arrives before its payment is retried after both `order.paid` and `payment.captured`. If the two retries overlap, both insert the refund and the second fails on `refunds_provider_refund_id_key`. Its catch then writes that error onto the event with `needs_review`, overwriting the clean result. Fix: `INSERT … ON CONFLICT (provider_refund_id) DO NOTHING`, then re-read the row `FOR UPDATE`, so the second retry waits and does nothing. Regression test added; it fails with the duplicate-key error without the fix.
- **Sign-off script bugs** (scripts/signoff-local.mjs). It could reuse the previous code from Mailpit before the new one landed, so the code login got `OTP_INVALID`. Now each message is used only once. It also sent no phone number, so holds got `PHONE_REQUIRED` (vendors require a phone by default, as the web form does). Now it sends one.
- **Tests that failed intermittently under load:** the AU-04 timing test hit the 5 s default timeout (it makes 13 argon2id requests), and the two code-polling loops in hardening.test.ts gave up after 2 s. The timeout and the waits were raised; no assertion was weakened.
- **Environment after moving the repo** (not code): the pnpm links in `node_modules` and the `apps/web/.next` cache were broken by the move (`Cannot find module 'tsx/cli'`; `/[slug]/book` answered 500 with a missing `routes-manifest.json`). Fixed with `pnpm install --frozen-lockfile` and by deleting `apps/web/.next`. After moving a folder, do both.
